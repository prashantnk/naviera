## 5. Playbook for Adding New Tests

1. **Pure Backend Unit Test (Preferred — fast, no DB, runs in `--quick`):**
   - Add to an existing `backend/scripts/tests/test_*_unit.py` file (or create a new file and register it in `PURE_UNIT_SUITES` inside `backend/scripts/run_golden.sh`).
   - Note: `backend/scripts/tests/conftest.py` automatically skips the Postgres savepoint fixture for modules registered in `PURE_TEST_FILES` (or named `*_unit.py` without DB fixtures). If creating a new pure unit file, add its filename to `PURE_TEST_FILES` in `backend/scripts/tests/conftest.py` and `PURE_UNIT_SUITES` in `backend/scripts/run_golden.sh`.
2. **DB-Backed Savepoint Unit Test:**
   - Add to `backend/scripts/tests/test_money_w2a.py`, `test_money_w2b.py`, `test_money_guards.py`, or another suite in `FULL_UNIT_SUITES` (`backend/scripts/run_golden.sh`).
   - **Advisory Lock Warning (`BUG-03`):** Never run DB savepoint unit tests concurrently while manual or automated API/UI journeys are booking shipments on `logismart-test`, because the outer savepoint transaction holds `pg_advisory_xact_lock` on the tenant's GST document series until the test function finishes.
3. **Golden API Journey (`J01–J69`):**
   - Add new multi-step HTTP + DB journeys to `backend/scripts/tests/golden_journeys/test_suite_14_phase1_gaps.py` (next ID: `J70`).
   - Remember that running any `golden_journeys/` file executes the session-scoped `golden_tenant_ready` fixture, which **resets `logismart-test`**.
4. **UI Golden E2E Test (`backend/scripts/tests/ui_golden/`):**
   - Use semantic `[data-testid="..."]` selectors from `backend/scripts/tests/ui_golden/testids.py`, assert DOM == Postgres rupee parity via `DbOracle`, and call `assert_no_horizontal_overflow` (`1440×900` and `390×844`).
5. **Keep This Catalog Updated:**
   - Whenever you add a new flow, endpoint, bug fix, or test file, update **Section 1** ("Changed X → Rerun Y"), **Section 2** (Flow Registry), and **Section 4.2** (Bug-to-Regression-Test Ledger) in `.agents/knowledge/test-catalog.md`.
